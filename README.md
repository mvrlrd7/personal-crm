# Личная CRM

Приложение для людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки после разговоров.
Идея и критерии успеха — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что мы сделали

1. **Собрали приложение по спеке.** Next.js + TypeScript, интерфейс на shadcn/ui, база PostgreSQL в Docker, таблицы описаны в коде через Drizzle. Данные читаются и сохраняются только на сервере.
2. **Сделали главный сценарий:** список всех контактов с мгновенным поиском по имени, добавление и редактирование контакта, карточка контакта с заметками (каждая со своими датой и временем, новые сверху), удаление контакта вместе с заметками — после подтверждения.
3. **Заполнили базу тестовыми данными:** 1000 вымышленных контактов и около 1800 заметок (`scripts/seed.ts`).
4. **Проверили критерии успеха** в Chrome через расширение Claude и в Edge: список виден целиком; добавленный контакт находится по имени, а заметка сохраняется; в другом браузере видны те же данные.
5. **Оформили приложение в стиле лендинга:** те же цвета (чёрный, белый, красный, жёлтый, синий), шрифт Golos Text, чёрные линии без скруглений и теней, жёлтые кнопки. Список контактов и заметки нарисованы по образцам из макета лендинга, карточка контакта — как карточка на лендинге. У каждого контакта свой цвет — синий, жёлтый или красный; он выбирается по имени, поэтому после смены имени может поменяться.

6. **Настроили автовыкатку на сервер:** после `git push` в `main` новая версия сама собирается и запускается на **https://app.remembr.cc** вместе со своей базой данных. Как это работает — в разделе «Как выкатить».

Пока нет: удаления отдельных заметок, входа и регистрации, уведомлений.

## Как запустить

Каждый раз, например после перезагрузки компьютера:

1. Запустите **Docker Desktop** и дождитесь, пока он загрузится.
2. Откройте терминал в папке проекта и выполните:
   ```bash
   pnpm db:up    # запустить базу данных
   pnpm start    # запустить приложение
   ```
3. Откройте в Chrome **http://localhost:3000**

Пока пользуетесь приложением, не закрывайте терминал. Данные сохраняются между запусками.

   ```bash
   pnpm build        # собрать приложение
   pnpm start        # запустить
   ```

## Как остановить

1. Щёлкните мышкой в окне терминала, где запущено приложение, и нажмите `Ctrl + C`. Если появится вопрос «Завершить выполнение пакетного файла [Y(да)/N(нет)]?» (или «Terminate batch job (Y/N)?»), нажмите `Y` и Enter. Приложение остановлено, когда снова появилась строка для ввода команды.
2. Терминал не реагирует — закройте его окно крестиком, приложение остановится вместе с ним.
3. Окна уже нет или непонятно, где запускали, — откройте новое окно PowerShell и выполните:
   ```powershell
   Stop-Process -Id (Get-NetTCPConnection -LocalPort 3000 -State Listen).OwningProcess
   ```
   Команда останавливает программу, которая занимает адрес localhost:3000. Красная ошибка в ответ — приложение уже не работает.

Проверка: откройте http://localhost:3000 — браузер должен написать, что сайт недоступен.

## Как выкатить

Приложение работает на сервере: **https://app.remembr.cc**

Чтобы выкатить новую версию, отправьте изменения в ветку `main` (`git push`). Дальше всё идёт само, обычно за 1–3 минуты:

1. **GitHub Actions** собирает образ приложения и кладёт его в **GHCR** (хранилище образов GitHub). Метка образа — SHA коммита, то есть номер версии.
2. Копирует на сервер скрипты из папки `deploy/` и запускает `deploy/deploy.sh`.
3. На сервере скрипт применяет миграции базы — отдельным разовым контейнером из того же образа. Если миграции упали, новая версия не запускается, работает старая.
4. Запускает новую версию и проверяет адрес `/health` (smoke-проверка): приложение должно ответить «ok», значит, оно работает и видит базу.
5. Удаляет старые образы: на сервере остаются только текущий и предыдущий.

Как следить: вкладка **Actions** в репозитории на GitHub. Зелёная галочка — версия выкатилась. Красный крестик — выкатка упала, в логе шага видно, на чём.

Проверить руками: откройте https://app.remembr.cc/health — должно быть `{"status":"ok"}`.

### Если выкатка упала или новая версия сломалась

Сама выкатка ничего не откатывает. Вернуть последнюю рабочую версию — вручную, одной командой в терминале:

```bash
ssh crm bash ~/personal-crm/deploy/rollback.sh
```

Откат возвращает только приложение, не базу. Если новая версия меняла таблицы, старая может с ними не заработать — тогда сначала разберитесь, в чём дело.

<details>
<summary>Что лежит на сервере</summary>

- `~/personal-crm/.env` — пароль и имя базы. Права 600: читает только владелец. В git его нет.
- `~/personal-crm/deploy/` — скрипты выкатки, каждая выкатка их обновляет из репозитория.
- `~/personal-crm/current-tag` и `previous-tag` — какая версия работает сейчас и какая была до неё.
- docker compose, проект `prod`: `crm-db` — база (данные хранятся в томе `prod_crm-db-data`), `crm-app` — приложение, `crm-migrate` — разовый контейнер для миграций. Логи каждого контейнера — не больше 30 МБ.
- nginx: `app.remembr.cc` передаёт запросы приложению на `127.0.0.1:3000`.

В GitHub: секрет `DEPLOY_SSH_KEY` — ключ, которым выкатка заходит на сервер; переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` — адрес сервера, пользователь и отпечаток сервера.
</details>

## Справка

- **Node.js** — программа, которая запускает JavaScript на компьютере, а не в браузере. На нём работает сервер приложения.
- **pnpm** — менеджер пакетов для Node.js. Скачивает библиотеки, из которых собрано приложение (список — в `package.json`, точные версии — в `pnpm-lock.yaml`), и запускает команды проекта: `pnpm start`, `pnpm build` и другие.
- **Docker Desktop** — программа, в которой работает база данных PostgreSQL, отдельно от остальной системы.

## Как устроено

- `src/app` — страницы: список контактов (`/`), новый контакт, карточка контакта, редактирование
- `src/app/actions.ts` — сохранение данных (выполняется на сервере)
- `src/lib/contacts.ts` — запросы к базе; браузер к базе не обращается
- `src/app/tokens.css` — цвета, шрифт, размеры текста и отступы; те же, что у лендинга (менять только здесь)
- `src/db/schema.ts` — таблицы `contacts` и `notes`, миграции — в папке `drizzle/`
- `scripts/seed.ts` — генератор тестовых данных, `scripts/migrate.ts` — миграции на сервере
- `src/app/health` — адрес `/health` для проверки после выкатки
- `Dockerfile` — как собирается образ приложения, `.github/workflows/deploy.yml` — автовыкатка, `deploy/` — скрипты выкатки и отката на сервере

Подключение к базе берётся из `.env`: переменные `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` (те же, что использует `docker-compose.yml`), а также необязательные `POSTGRES_PORT` (по умолчанию 5432) и `POSTGRES_HOST` (по умолчанию 127.0.0.1). Вместо них можно задать одну строку `DATABASE_URL`.
