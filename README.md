# Личная CRM

Приложение для людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки после разговоров.
Идея и критерии успеха — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что мы сделали

1. **Собрали приложение по спеке.** Next.js + TypeScript, интерфейс на shadcn/ui, база PostgreSQL в Docker, таблицы описаны в коде через Drizzle. Данные читаются и сохраняются только на сервере.
2. **Сделали главный сценарий:** список всех контактов с мгновенным поиском по имени, добавление и редактирование контакта, карточка контакта с заметками (каждая со своими датой и временем, новые сверху).
3. **Заполнили базу тестовыми данными:** 1000 вымышленных контактов и около 1800 заметок (`scripts/seed.ts`).
4. **Проверили критерии успеха** в Chrome через расширение Claude и в Edge: список виден целиком; добавленный контакт находится по имени, а заметка сохраняется; в другом браузере видны те же данные.

Пока нет: удаления контактов и заметок, входа и регистрации, уведомлений.

## Как запустить

Каждый раз, например после перезагрузки компьютера:

1. Запустите **Docker Desktop** и дождитесь, пока он загрузится.
2. Откройте терминал в папке проекта и выполните:
   ```bash
   pnpm db:up    # запустить базу данных
   pnpm start    # запустить приложение
   ```
3. Откройте в Chrome **http://localhost:3000**

Пока пользуетесь приложением, не закрывайте терминал. Остановить приложение — `Ctrl + C`. Данные сохраняются между запусками.

## Справка

- **Node.js** — программа, которая запускает JavaScript на компьютере, а не в браузере. На нём работает сервер приложения.
- **pnpm** — менеджер пакетов для Node.js. Скачивает библиотеки, из которых собрано приложение (список — в `package.json`, точные версии — в `pnpm-lock.yaml`), и запускает команды проекта: `pnpm start`, `pnpm build` и другие.
- **Docker Desktop** — программа, в которой работает база данных PostgreSQL, отдельно от остальной системы.

## Все команды

| Команда            | Что делает                                                             |
| ------------------ | ---------------------------------------------------------------------- |
| `pnpm dev`         | запуск в режиме разработки: изменения в коде видны сразу                |
| `pnpm build`       | сборка приложения                                                      |
| `pnpm start`       | запуск собранного приложения                                           |
| `pnpm db:up`       | запустить базу данных в Docker                                         |
| `pnpm db:generate` | создать файл миграции после изменения схемы в `src/db/schema.ts`       |
| `pnpm db:migrate`  | применить миграции к базе                                              |
| `pnpm db:seed`     | заполнить пустую базу тестовыми данными                                |
| `pnpm db:studio`   | открыть просмотр базы в браузере (Drizzle Studio)                      |
| `pnpm lint`        | проверить код линтером                                                 |
| `pnpm typecheck`   | проверить типы TypeScript                                              |

## Как устроено

- `src/app` — страницы: список контактов (`/`), новый контакт, карточка контакта, редактирование
- `src/app/actions.ts` — сохранение данных (выполняется на сервере)
- `src/lib/contacts.ts` — запросы к базе; браузер к базе не обращается
- `src/db/schema.ts` — таблицы `contacts` и `notes`, миграции — в папке `drizzle/`
- `scripts/seed.ts` — генератор тестовых данных

Подключение к базе берётся из `.env`: переменные `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` (те же, что использует `docker-compose.yml`), а также необязательные `POSTGRES_PORT` (по умолчанию 5432) и `POSTGRES_HOST` (по умолчанию 127.0.0.1). Вместо них можно задать одну строку `DATABASE_URL`.
